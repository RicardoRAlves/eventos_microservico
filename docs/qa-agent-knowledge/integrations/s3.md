Três serviços usam AWS SDK S3 com bucket/região/credenciais por ambiente e suporte opcional a endpoint, path-style e URL pública. Local usa RustFS em `localhost:4566` e bucket inicializado com política pública de leitura.

Event e user preservam o filename como key e só rejeitam nome nulo/vazio; enviam content-type se presente. O limite explícito de 2 MB existe apenas nas propriedades do event_api. Não foi encontrada validação de magic bytes ou allowlist MIME nesses dois serviços.

Organization cria key `organizations/{slug}/{slug}.{extension}`; o mesmo nome tende a sobrescrever a imagem anterior. Aceita extensão baseada em filename ou MIME e limita MIME reconhecido a JPEG/PNG/WebP quando precisa inferir. O slug normaliza Unicode e usa UUID se vazio.

Os três serviços possuem `deleteImage`, com validação rigorosa de origem/bucket para URL pública configurada e padrões AWS virtual-host/path-style, mas nenhum fluxo de produção chama esse método no código analisado. Upload não atualiza entidade automaticamente.

Riscos de teste: bucket externo acidental, objetos órfãos, upload público sem auth no user_api, sobrescrita de logo e ausência de limpeza. Testes READY devem usar apenas RustFS/bucket descartável.
